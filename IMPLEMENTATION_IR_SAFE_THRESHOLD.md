## Public graph property

Add a graph-level DOT attribute named `threshold_counterterms`. Its value is an embedded, versioned TOML document. The public representation is always compact and organized as:

```text
cut → threshold → counterterm variants
```

It never contains `side`, left×right pairs, or expanded local/integrated terms. Side inference and all Cartesian products remain internal to GammaLoop, including under `save dot --include-autogenerated-fields`. Amplitudes use the identical schema with `cuts.edges = []`.

The following is illustrative pseudocode based on the historical GL638 mapping. Its numerical IDs must be verified before use:

```toml
schema_version = 1

[[cuts]]
edges = [2, 4, 12] # provisional GL638 mapping

  [[cuts.thresholds]]
  edges = [7, 8] # provisional GL638 mapping

    [[cuts.thresholds.counterterms]]
    name = "intrinsic_1l"
    subspace = [7] # provisional basis-edge mapping

      [cuts.thresholds.counterterms.multiplier]
      expression = "1 / (1 + (eta(effective, eset(7, 8)) / UFO::MT)^2)"
      symmetrize = false
      opaque_derivatives = true

    [[cuts.thresholds.counterterms]]
    name = "embedded_2l"
    subspace = [3, 7] # provisional basis-edge mapping

      [cuts.thresholds.counterterms.multiplier]
      expression = "(eta(effective, eset(7, 8)) / UFO::MT)^2 / (1 + (eta(effective, eset(7, 8)) / UFO::MT)^2)"
      symmetrize = false
      opaque_derivatives = true

  [[cuts.thresholds]]
  edges = [5, 12, 13] # provisional right-side partner

    [[cuts.thresholds.counterterms]]
    name = "default"
    # Omitted subspace invokes the existing maximal-subspace behavior.
    # Omitted multiplier means identity and creates no evaluator.
```

Historical research suggests repeating the duplicated threshold block under four GL638 cuts and pairing it with two right thresholds under one cut. The implementation must rediscover the actual current associations rather than assume the recorded tuples are still correct. The expressions above are safe illustrative smoke-test functions, not the final physics prescription.

Use strict typed parsing with unknown-field rejection:

- Root: `schema_version = 1`, `cuts = []`.
- Cut: required unordered `edges`; `thresholds = []`.
- Threshold: required unordered full-graph `edges`; `counterterms = []`.
- Counterterm: optional `name`, ordered `subspace`, optional ordered `parent_lmb`, `disable = false`, optional `multiplier`.
- Multiplier: required nonblank `expression`, `symmetrize = false`, `opaque_derivatives = true`.
- Reject unsupported schema versions and `opaque_derivatives = false`.
- Parse and round-trip `symmetrize = true`, but stop during preprocessing with a clear `unimplemented!(...)`.
- Canonicalize set-like cut/threshold edge lists; preserve the order of `subspace` and `parent_lmb`.
- Validate edge ranges, duplicates, internal/basis-edge eligibility, duplicate canonical cuts or thresholds, and variant names.
- A single unnamed variant becomes `default`; multiple variants require unique, nonblank names.

Defaults preserve current behavior exactly:

- An absent graph attribute becomes an autogenerated empty v1 document internally.
- A missing cut, missing threshold, omitted/empty `counterterms`, or omitted `subspace` resolves through GammaLoop’s existing legacy maximal-subspace construction with identity multiplier.
- A nonempty explicit variant list replaces the implicit default.
- To request legacy plus a custom duplicate, explicitly list a legacy variant with omitted subspace and multiplier.
- An association whose explicitly listed variants are all disabled remains disabled and receives no fallback.
- Identity multipliers are represented by `None` and allocate no evaluator.

Implement a reversible embedded-document codec. Decode DOT escapes before TOML parsing and correctly round-trip quotes, backslashes, newlines, tabs, and Unicode. Apply graph-import edge permutations to every directive edge: sort remapped set-like lists while preserving ordered-list order.

## Raw, resolved, and exported representations

Maintain two layers:

- `Graph` owns `Autogen<ThresholdCountertermSpec>`, preserving whether the compact document was explicit or autogenerated.
- Amplitude and cross-section derived data independently own `Option<ResolvedThresholdCounterterms>`, containing stable variant IDs, inferred side, resolved parent/subspace, provenance, eligibility, and runtime links.
- Grouped-amplitude directives remain on each member graph; group maps may reference member-local IDs but never relocate or merge their configuration.
- Iterated pair identities and L/I components remain generated runtime data and are never placed in either DOT representation.

Resolution is atomic: clear stale resolved data before preprocessing, build and validate a temporary result, and install it only after success.

Export semantics are:

| State | Ordinary `save dot` | `--include-autogenerated-fields` |
|---|---|---|
| Attribute absent, before preprocessing | Omit it | Emit canonical `schema_version = 1; cuts = []` |
| Explicit partial document, before preprocessing | Emit canonical explicit content | Emit the same content without triggering generation |
| After successful preprocessing | Emit only explicit compact declarations | Emit explicit declarations plus every eligible synthesized legacy-default association from that preprocessing context |

Materialized defaults contain `name = "default"` and the actual resolved maximal subspace. Emit `parent_lmb` only when required to reproduce the same embedding; omit the multiplier table for identity. Explicit dormant declarations remain preserved, while generated completion covers only associations eligible in the last successful preprocessing context.

Process-level graph exporters must pass the wrapper’s resolved view instead of bypassing it and serializing only the inner graph. A normalized-default DOT re-import must be recognized by semantic equivalence as legacy and remain on the homogeneous fast path; explicit provenance alone must not force the generalized runtime path.

## Resolution, variants, and subspaces

Resolve directives after topology, physical-cut, raised-group, and E-surface discovery, but before current cut-group aggregation and deduplication:

- Match explicit declarations by canonical `(physical cut edges, threshold energy edges)`; amplitude cut edges are empty.
- Infer left/right placement topologically.
- A declaration filtered out solely by the selected orientation is dormant, not invalid.
- Require physical cuts sharing one raised-cut residue to resolve compatible variants before aggregation; reject conflicts contextually.
- Give every resolved cut/threshold/variant association a stable semantic ID. Duplicate geometric thresholds with different variants remain independent in overlap finding, multichanneling, roots, metadata, and events.
- Memoize identical residue-selector/CutWoods algebra when possible without merging semantic IDs.

Replace cut-side-wide subspace assumptions with per-variant data:

- Retain the ordered requested basis-edge list separately.
- Extend the existing `SubspaceData` abstraction to map ordered parent-basis edges back to the active subgraph/subspace; no parallel helper API is needed.
- Prefer the current cut-compatible parent LMB, then equivalent generated compatible LMBs. Require `parent_lmb` only when genuinely different embeddings remain.
- Validate independence, containment on the inferred cut side, radial dependence, loop count, and fixed complement.
- For every internally generated left×right pair, require a common parent LMB and disjoint/mergeable active indices. Reject incompatible combinations instead of merging arbitrary frames.
- Generate the radial Jacobian with the variant’s own loop count, `r_star^(3 L_v - 1)`.

Generalize overlap and multichannel structures to variant IDs. Mixed-subspace overlap candidates must admit a common canonical center satisfying every variant’s E-surface and fixed-complement constraints. Preserve the current homogeneous no-directive center/root path unchanged.

## Multiplier ABI and expanded-term semantics

V1 exposes one fixed, cut-owned input layout shared by every multiplier under that cut:

- All active model parameters in existing model order.
- All external four-momenta `P`.
- `Q3` for every graph edge in `effective` and `star` views.
- Every uniquely resolvable E-surface equation `eta` relevant to the owning physical/raised cut group, including resolved threshold associations, in both views.

Accepted syntax is:

```text
Q3(edge, lorentz_index)                  # effective alias
Q3(effective, edge, lorentz_index)
Q3(star, edge, lorentz_index)

eta(eset(edge_0, edge_1, ...))                 # effective alias
eta(effective, eset(edge_0, edge_1, ...))
eta(star, eset(edge_0, edge_1, ...))

P(external_position, lorentz_index)
UFO::<model parameter>
```

`Q3` reuses GammaLoop’s existing spatial-momentum tensor. It remains Lorentz-indexed for Spenso, but its temporal component is exactly zero; Minkowski contraction therefore introduces the understood minus sign relative to a Euclidean spatial dot product. Reject multiplier `Q` and `K` with guidance to use `Q3`.

Resolve each canonical, duplicate-free `eta` edge set against the owning cut’s fixed E-surface catalog. If identical energy edges correspond to different external shifts in that catalog, reject the call as ambiguous instead of choosing silently.

The `eset` head is mandatory and is registered with Symbolica's symmetric
attribute before parsing, so callers may write its edge arguments in any
order. Flat `eta` edge arguments are rejected rather than accepted through a
backward-compatibility lane.

Parse expressions during generation, pass tensor expressions through the existing Spenso network/contraction machinery, and require one scalar Symbolica result. Reject free tensor indices, invalid frame names, unknown symbols, invalid edge/external IDs, and non-scalar results with graph/cut/threshold/variant context. At runtime require a finite, real result in the active f64, f128, or arbitrary-precision lane.

The user’s nine-term interpretation is valid: current GammaLoop already generates distinct single associations and each left×right residue pair, so a selected pair has unambiguous roots. What is currently hidden is the L/I expansion inside helper evaluators. Split helper outputs while sharing their CSE and residue evaluation:

```text
SingleThresholdPieces   { local, integrated }
IteratedThresholdPieces { local_local, local_integrated,
                          integrated_local, integrated_integrated }
```

“Local” includes the PV/simple-pole local piece and every raised local pole. “Integrated” is the localized integrated simple-pole piece.

Use the following normative global sample contexts:

| Component | `effective` view | `star` view |
|---|---|---|
| `L_left × O_right` | base | left root |
| `I_left × O_right` | left root | left root |
| `O_left × L_right` | base | right root |
| `O_left × I_right` | right root | right root |
| `L_left × L_right` | base | merged left/right roots |
| `I_left × L_right` | left root | merged roots |
| `L_left × I_right` | right root | merged roots |
| `I_left × I_right` | merged roots | merged roots |

A missing/original side is the identity transformation, so its spectator coordinates remain at the base sample. Both multiplier evaluators in an iterated term receive exactly the same global `effective`/`star` slice. The factorized bracket formula is therefore literal for side-local functions; for cross-dependent functions, this table is the authoritative termwise definition.

Evaluate multipliers from non-dual values and lift them as constants after HyperDual/two-pass differentiation. Apply them to the corresponding completed local/integrated/raised component. Because expressions may inspect `star`, pointwise zero cannot generally remove a variant before classification, overlap, center, or root construction.

After all required contexts exist:

- Evaluate and finite/real-validate every participating factor, even when another factor is zero.
- Single coefficient is `f`; pair coefficient is `f_left * f_right`.
- Exact zero in the active precision removes only that expanded algebraic component.
- If both single coefficients or all four pair coefficients are zero, skip the shared residue/helper evaluation.
- If only some are zero, evaluate the residue once and combine only surviving completed components.
- Do not recompute overlap or multichannel normalization based on pointwise zeros.
- Record skipped-zero state explicitly in diagnostics/events.

- Transform and cache base, each left root, each right root, and each merged pair in the graph’s generation LMB.

- Evaluate a shared expression once when both sides reference the same evaluator and context.
- Allocate no multiplier layout/evaluator/workspace on the identity/no-directive path.

Add a per-integrand metadata registry containing stable variant, evaluator, and expanded-component IDs plus graph/name, origin, cut and threshold provenance, inferred side, requested/resolved subspace and parent, loop count, expression, and flags. ## Addendum: projected variants are independent subtraction surfaces

For overlap-center and COSP construction, treat every resolved counterterm variant as an independent projected E-surface, even when two variants originate from the same supergraph E-surface. Each variant still has exactly one resolved subspace and one fixed-complement constraint; “mixed” refers only to an overlap candidate containing several such independently projected variants, never to one counterterm being solved in more than one subspace.

- Give each projected variant its own semantic surface identity and include it independently in the existing COSP program.
- Impose that variant's own subspace and fixed-complement constraints when finding a common center.
- Do not use the shared supergraph energy-edge set to merge variants or relax those constraints in v1. A later refinement may exploit their common origin without changing the public schema.
- Keep the original×original contribution unique. One-sided variant×original records and left×right variant pairs contribute only their counterterm pieces; the original side is an identity kinematic transformation, not another copy of the original integrand.

## Addendum: mandatory symmetric E-surface sets

Every multiplier-language `eta` call wraps its energy-edge arguments in the
Symbolica-symmetric `eset` head. Accepted forms are exactly
`eta(eset(...))`, `eta(effective, eset(...))`, and
`eta(star, eset(...))`; the flat historical forms are invalid. Symbolica
canonicalizes permutations of `eset` arguments during parsing.

The view name remains semantically significant. In an integrated expanded
component, the global `effective` view is already replaced by that component's
threshold root, while in a local component it remains the local sample. The
`star` view always exposes the applicable root or merged-root sample. The
curing GL638 prescription uses `effective`: it is the local `r` sample for a
local component and is already replaced by `r_star` for an integrated
component. This realizes the required `f(r)`/`f(r_star)` behavior and preserves
the integrated CT's PV-zero property. Using explicit `star` for this ratio
would instead evaluate the owning E-surface at its root even for local pieces,
collapsing the two local branches to zero and one rather than multichanneling
them. A left×right term still passes one global effective/star context to both
functions, so the duplicated variants and full Cartesian expansion remain
necessary.
