1//! # Half-Edge Graph Representation
2//!
3//! This module provides the core data structures and algorithms for representing
4//! and manipulating graphs using the **half-edge** (or doubly connected edge list - DCEL)
5//! data structure. This representation is particularly useful for algorithms that
6//! require efficient traversal of graph topology, such as iterating around faces,
7//! finding incident edges to a node, or quickly accessing an edge's opposite pair.
8//!
9//! ## Key Concepts and Components:
10//!
11//! ### 1. `HedgeGraph<E, V, S>`
12//! This is the central struct representing a graph.
13//!   - `E`: Generic type for data associated with edges.
14//!   - `V`: Generic type for data associated with nodes (vertices).
15//!   - `S`: A type implementing `NodeStorage`, which defines how node data and their connectivity to half-edges are stored.
16//!
17//! `HedgeGraph` stores half-edges in an `edge_store` (typically `SmartHedgeVec`)
18//! and nodes in a `node_store`.
19//!
20//! ### 2. `Hedge` and `NodeIndex`
21//!   - `Hedge`: An identifier (often an index) for a single directed half-edge.
22//!     Each undirected edge in the graph is typically represented by two oppositely
23//!     directed half-edges.
24//!   - `NodeIndex`: A simple wrapper around `usize` used to identify nodes in the graph.
25//!
26//! ### 3. Involutions (`involution` module)
27//! A crucial concept in this implementation is the **involution** on half-edges.
28//! An involution is a function that, when applied twice, returns the original input.
29//! In the context of a half-edge graph, the primary involution is finding the
30//! **opposite half-edge**.
31//!   - `Involution`: The struct managing this mapping.
32//!   - `HedgePair`: Represents how hedges are paired (e.g., forming a full edge,
33//!     being unpaired/dangling, or split).
34//!   - `Flow`: Indicates the underlying directionality of a half-edge (Source or Sink)
35//!     relative to its edge.
36//!   - `Orientation`: Indicates the superficial orientation of an edge (Default, Reversed,
37//!     Undirected).
38//!
39//! The `inv(hedge: Hedge) -> Hedge` method on `HedgeGraph` is the primary way to
40//! access the opposite half-edge.
41//!
42//! ### 4. Node Storage (`nodestore` module)
43//! This module defines how nodes are stored and how they relate to the half-edges
44//! that originate from them.
45//!   - `NodeStorage` trait: An abstraction for different node storage strategies.
46//!   - `NodeStorageOps` trait: Provides operations on node storage.
47//!   - Each node typically stores a collection of its outgoing (or incident) half-edges.
48//!
49//! ### 5. Subgraphs (`subgraph` module)
50//! This module provides extensive support for defining, manipulating, and querying
51//! subgraphs. A subgraph is essentially a subset of the half-edges of a parent graph.
52//!   - `SubGraph` trait: Defines the basic interface for a subgraph.
53//!   - `SubGraphOps` trait: Provides operations applicable to subgraphs.
54//!   - Various concrete subgraph types exist, such as:
55//!     - `InternalSubGraph`: Represents a subgraph composed of edges internal to a region.
56//!     - `HedgeNode`: Represents a "node" in a higher-level graph structure, possibly
57//!       formed by contracting a subgraph. It contains an `internal_graph` and `hairs`
58//!       (external connections).
59//!     - `Cycle`: Represents a cycle in the graph.
60//!     - `OrientedCut`: Represents a cut separating the graph.
61//!
62//! Operations include creating subgraphs from filters, extracting subgraphs,
63//! performing boolean operations (union, intersection, difference), and analyzing
64//! subgraph properties.
65//!
66//! ### 6. Graph Operations
67//! The `HedgeGraph` provides a rich API for:
68//!   - **Construction**: Building graphs using `HedgeGraphBuilder`, adding nodes and edges
69//!     (`add_dangling_edge`, `add_pair`).
70//!   - **Modification**: Deleting hedges (`delete_hedges`), splitting edges (`split_edge`),
71//!     joining graphs (`join`), sewing dangling edges (`sew`), and identifying/contracting
72//!     nodes (`identify_nodes`).
73//!   - **Traversal & Access**: Getting an edge's opposite (`inv`), finding the node a
74//!     hedge points to (`node_id`), iterating over neighbors (`iter_crown`), and
75//!     accessing edge/node data.
76//!   - **Analysis**: Checking connectivity (`is_connected`), counting components
77//!     (`count_connected_components`), finding cycle bases (`cycle_basis`), spanning trees
78//!     (`all_spanning_forests_of`), and calculating cyclotomatic numbers.
79//!   - **Serialization/Visualization**: Generating DOT format strings for graph visualization.
80//!
81//! This module forms the backbone of the `linnet` library, enabling complex graph
82//! manipulations with a focus on subgraphs and topological features.

241/// The main graph data structure, representing a graph using the half-edge
242/// (or doubly connected edge list - DCEL) principle.
243///
244/// A `HedgeGraph` stores nodes and edges (represented as pairs of half-edges).
245/// It is generic over the data associated with edges (`E`), nodes/vertices (`V`),
246/// and the specific storage strategy used for nodes (`S`).
247///
248/// The half-edge representation allows for efficient traversal of graph topology,
249/// such as iterating around faces (in planar embeddings), finding incident edges
250/// to a node, or quickly accessing an edge's opposite half-edge.
251///
252/// # Type Parameters
253///
254/// - `E`: The type of data associated with each edge (or pair of half-edges).
255/// - `V`: The type of data associated with each node (vertex).
256/// - `S`: The node storage strategy, implementing the [`NodeStorage`] trait.
257///   This determines how node data and their connectivity to half-edges
258///   are stored. Defaults to [`DefaultNodeStore<V>`] (feature-selected; `nodestore-vec` uses
259///   [`nodestore::NodeStorageVec<V>`]).
260pub struct HedgeGraph<E, V, H = NoData, S: NodeStorage<NodeData = V> = DefaultNodeStore<V>> {
261    pub(crate) hedge_data: HedgeVec<H>,
262    /// Internal storage for all half-edges, their data, and their topological
263    /// relationships (e.g., opposite half-edge, next half-edge around a node).
264    /// This is typically a [`SmartHedgeVec<E>`].
265    pub(crate) edge_store: SmartEdgeVec<E>,
266    /// Storage for all nodes in the graph, including their data (`V`) and
267    /// information about the half-edges incident to them.
268    /// The specific implementation is determined by the `S` type parameter.
269    pub node_store: S,
270}

296    /// Creates a random graph with a specified number of nodes and edges.
297    ///
298    /// The graph generated will have `()` as edge data and default values for node data `V`.
299    /// The structure of the graph (connectivity) is determined randomly based on the provided seed.
300    ///
301    /// # Parameters
302    /// - `nodes`: The desired number of nodes in the graph.
303    /// - `edges`: The desired number of edges (pairs of half-edges) in the graph.
304    /// - `seed`: A seed for the random number generator to ensure reproducibility.
305    ///
306    /// # Returns
307    /// A new `HedgeGraph<(), V, N>` with a random structure.
308    ///
309    /// # Constraints
310    /// - `N::Neighbors` must implement `BaseSubgraph` and `SubGraphOps`.
311    /// - `V` must implement `Default`.
312    ///
313    /// # Panics
314    /// Panics if `sources.len()` (derived from `edges`) is 0 when `externals` (unpaired half-edges)
315    /// is not empty, or if `sinks.len()` is 0 when `externals` is not empty. This can occur if
316    /// `edges` is too small relative to the internal logic of pairing, leading to attempts to access
317    /// empty vectors `sources` or `sinks`. Also panics if node merging logic (to reduce node count
318    /// to `nodes`) attempts to operate on empty or insufficiently small `sources` or `sinks` lists.
319    pub fn random(nodes: usize, edges: usize, seed: u64) -> HedgeGraph<(), V, H, N>
320    where
321        N::Neighbors: BaseSubgraph + SubSetOps + ModifySubSet<Hedge>,
322        <<N as NodeStorage>::Neighbors as SubSetLike>::Base: SubSetOps,
323    {
324        let inv: Involution<()> = Involution::<()>::random(edges, seed);
325
326        let mut rng = SmallRng::seed_from_u64(seed);
327
328        let mut externals = Vec::new();
329        let mut sources = Vec::new();
330        let mut sinks = Vec::new();
331
332        for (i, e) in inv.iter() {
333            let n_h: Hedge = inv.len();
334            let mut nodeid = N::Neighbors::empty(n_h.0);
335            nodeid.add(i);
336            match e {
337                InvolutiveMapping::Identity { .. } => externals.push(nodeid),
338                InvolutiveMapping::Source { .. } => sources.push(nodeid),
339                InvolutiveMapping::Sink { .. } => sinks.push(nodeid),
340            }
341        }
342
343        assert_eq!(sources.len(), sinks.len());
344
345        while !externals.is_empty() {
346            if rng.gen_bool(0.5) {
347                let source_i = rng.gen_range(0..sources.len());
348
349                sources[source_i].union_with(&externals.pop().unwrap());
350            } else {
351                let sink_i = rng.gen_range(0..sinks.len());
352
353                sinks[sink_i].union_with(&externals.pop().unwrap());
354            }
355        }
356
357        let mut lengthone = false;
358
359        while sources.len() + sinks.len() > nodes {
360            if rng.gen_bool(0.5) {
361                if sources.len() <= 1 {
362                    if lengthone {
363                        break;
364                    }
365                    lengthone = true;
366                    continue;
367                }
368
369                let idx1 = rng.gen_range(0..sources.len());
370                let idx2 = rng.gen_range(0..sources.len() - 1);
371
372                let n_i = sources.swap_remove(idx1);
373                sources[idx2].union_with(&n_i);
374            } else {
375                if sinks.len() <= 1 {
376                    if lengthone {
377                        break;
378                    }
379                    lengthone = true;
380                    continue;
381                }
382                let idx1 = rng.gen_range(0..sinks.len());
383                let idx2 = rng.gen_range(0..sinks.len() - 1);
384                let n_i = sinks.swap_remove(idx1);
385                sinks[idx2].union_with(&n_i);
386            }
387        }
388
389        let mut hedge_data = HedgeVec::new();
390        let n_h: Hedge = inv.len();
391        for _ in 0..n_h.0 {
392            hedge_data.push(H::default());
393        }
394
395        HedgeGraph {
396            hedge_data,
397            node_store: N::random(&sources, &sinks),
398            edge_store: SmartEdgeVec::new(inv),
399        }
400    }
401}

403impl<E, V, H, N: NodeStorageOps<NodeData = V>> HedgeGraph<E, V, H, N> {
404    pub fn check(&self) -> Result<(), HedgeGraphError> {
405        // Check involution
406        for (h, _) in self.iter_hedges() {
407            if h != self.inv(self.inv(h)) {
408                Err(InvolutionError::NonInvolutive(h))?;
409            }
410        }
411
412        // Check smart edge vec
413        self.edge_store.check_hedge_pairs()?;
414        Ok(())
415    }

417    /// Deletes all half-edges specified in the `subgraph` from the graph.
418    ///
419    /// This operation modifies both the `edge_store` and `node_store` to remove
420    /// the specified half-edges and update connectivity information.
421    ///
422    /// # Parameters
423    /// - `subgraph`: A subgraph specifying the set of half-edges to delete.
424    ///   `S` must implement `SubGraph` with `Base = N::Base`.
425    pub fn delete_hedges<S: SubSetLike<Base = N::Base>>(&mut self, subgraph: &S) {
426        let mut left = Hedge(0);
427        let mut extracted: Hedge = self.len();
428        while left < extracted {
429            if !subgraph.includes(&left) {
430                //left is in the right place
431                left.0 += 1;
432            } else {
433                //left needs to be swapped
434                extracted.0 -= 1;
435                if !subgraph.includes(&extracted) {
436                    // println!("{extracted}<=>{left}");
437                    //only with an extracted that is in the wrong spot
438                    self.hedge_data.swap(left, extracted);
439                    left.0 += 1;
440                }
441            }
442        }
443        let _ = self.hedge_data.split_off(left);
444
445        self.edge_store.delete(subgraph);
446        self.node_store.delete(subgraph);
447    }

449    /// Creates a new `HedgeGraph` instance representing a "concretized" view of a given `subgraph`.
450    ///
451    /// This method effectively extracts the specified `subgraph` into a new, independent graph.
452    /// The new graph contains copies of the nodes and edges (and their data via references)
453    /// that are part of the `subgraph`.
454    ///
455    /// Node and edge data in the new graph are references (`&'a V`, `&'a E`) to the data
456    /// in the original graph.
457    ///
458    /// # Parameters
459    /// - `subgraph`: A reference to a subgraph `S` within the current graph.
460    ///
461    /// # Returns
462    /// A new `HedgeGraph` containing only the elements of the `subgraph`.
463    /// The node storage type of the new graph is `N::OpStorage<&'a V>`.
464    pub fn concretize<'a, S: SubSetLike>(
465        &'a self,
466        subgraph: &'a S,
467    ) -> HedgeGraph<&'a E, &'a V, &'a H, N::OpStorage<&'a V>> {
468        let mut builder = HedgeGraphBuilder::new();
469
470        let mut node_map = AHashMap::new();
471
472        for (n, _, d) in self.iter_nodes_of(subgraph) {
473            node_map.insert(n, builder.add_node(d));
474        }
475
476        for (pair, _, d) in self.iter_edges_of(subgraph) {
477            match pair {
478                HedgePair::Paired { source, sink } => {
479                    let src = node_map[&self.node_id(source)].add_data(&self[source]);
480                    let dst = node_map[&self.node_id(sink)].add_data(&self[sink]);
481
482                    builder.add_edge(src, dst, d.data, d.orientation);
483                }
484                HedgePair::Unpaired { hedge, flow } => {
485                    let src = node_map[&self.node_id(hedge)].add_data(&self[hedge]);
486
487                    builder.add_external_edge(src, d.data, d.orientation, flow);
488                }
489                HedgePair::Split {
490                    source,
491                    sink,
492                    split,
493                } => match split {
494                    Flow::Sink => {
495                        let src = node_map[&self.node_id(sink)].add_data(&self[sink]);
496                        builder.add_external_edge(src, d.data, d.orientation, split);
497                    }
498                    Flow::Source => {
499                        let src = node_map[&self.node_id(source)].add_data(&self[source]);
500                        builder.add_external_edge(src, d.data, d.orientation, split);
501                    }
502                },
503            }
504        }
505
506        builder.build()
507    }

509    /// Extracts a subgraph and transforms its data, potentially splitting edges and nodes
510    /// that are on the boundary of the subgraph.
511    ///
512    /// This is a more advanced operation than `concretize`. It allows for:
513    /// - Transforming edge data for edges fully within the subgraph (`internal_data` closure).
514    /// - Transforming edge data for edges that are split by the subgraph boundary (`split_edge_fn` closure).
515    /// - Transforming node data for nodes that are part of split edges (`split_node` closure).
516    /// - Transforming node data for nodes fully within the subgraph and taking ownership (`owned_node` closure).
517    ///
518    /// The result is a new `HedgeGraph` with transformed edge data `O` and node data `V2`.
519    ///
520    /// # Parameters
521    /// - `subgraph`: The subgraph `S` to extract.
522    /// - `split_edge_fn`: A closure that transforms `EdgeData<&E>` (for edges on the boundary)
523    ///   to `EdgeData<O>`.
524    /// - `internal_data`: A closure that transforms `EdgeData<E>` (for edges fully inside)
525    ///   to `EdgeData<O>`.
526    /// - `split_node`: A closure that transforms node data `&V` (for nodes on the boundary)
527    ///   to `V2`.
528    /// - `owned_node`: A closure that transforms node data `V` (for nodes fully inside, taking ownership)
529    ///   to `V2`.
530    ///
531    /// # Returns
532    /// A new `HedgeGraph<O, V2, N::OpStorage<V2>>` representing the extracted and transformed subgraph.
533    pub fn extract<O, V2, S: SubSetLike<Base = N::Base>>(
534        &mut self,
535        subgraph: &S,
536        split_edge_fn: impl FnMut(EdgeData<&E>) -> EdgeData<O>,
537        internal_data: impl FnMut(EdgeData<E>) -> EdgeData<O>,
538        split_node: impl FnMut(&V) -> V2,
539        owned_node: impl FnMut(V) -> V2,
540    ) -> HedgeGraph<O, V2, H, N::OpStorage<V2>> {
541        let new_edge_store = self
542            .edge_store
543            .extract(subgraph, split_edge_fn, internal_data);
544
545        let mut left = Hedge(0);
546        let mut extracted: Hedge = self.len();
547        while left < extracted {
548            if !subgraph.includes(&left) {
549                //left is in the right place
550                left.0 += 1;
551            } else {
552                //left needs to be swapped
553                extracted.0 -= 1;
554                if !subgraph.includes(&extracted) {
555                    // println!("{extracted}<=>{left}");
556                    //only with an extracted that is in the wrong spot
557                    self.hedge_data.swap(left, extracted);
558                    left.0 += 1;
559                }
560            }
561        }
562        let new_hedge_data = self.hedge_data.split_off(left);
563
564        let new_node_store = self.node_store.extract(subgraph, split_node, owned_node);
565        HedgeGraph {
566            hedge_data: new_hedge_data,
567            node_store: new_node_store,
568            edge_store: new_edge_store,
569        }
570    }

572    pub fn extract_nodes<O>(
573        &mut self,
574        nodes: impl IntoIterator<Item = NodeIndex>,
575        split_edge_fn: impl FnMut(EdgeData<&E>) -> EdgeData<O>,
576        internal_data: impl FnMut(EdgeData<E>) -> EdgeData<O>,
577    ) -> HedgeGraph<O, V, H, N>
578    where
579        N: NodeStorageOps<Base = SuBitGraph>,
580    {
581        let (extracted, nodes) = self.node_store.extract_nodes(nodes);
582
583        let left = self.hedge_data.partition(|h| !extracted.includes(h));
584
585        let ne_hedge = self.hedge_data.split_off(left);
586
587        let new_edge_store = self
588            .edge_store
589            .extract(&extracted, split_edge_fn, internal_data);
590        HedgeGraph {

918    /// Returns `true` for an empty subgraph.
919    ///
920    /// # Panics
921    /// Panics if the traversal (used internally) fails, which can happen if the
922    /// starting node for traversal is not part of the `subgraph`.
923    pub fn is_connected<S: SubGraphLike>(&self, subgraph: &S) -> bool {
924        if let Some(start) = subgraph.included_iter().next() {

926                self,
927                subgraph,
928                &self.node_id(start),
929                None,
930            )
931            .unwrap()
932            .covers(subgraph);
933            for h in subgraph.included_iter() {

936                }
937            }
938        }

942    /// Modifies a [`HedgeNode`] subgraph by removing "branches" or "tendrils".
943    ///
944    /// A branch is typically a path of edges within the `subgraph` that ultimately
945    /// connects to the rest of the `subgraph` at only one point (one node with degree > 1
946    /// within the branch, relative to other branch edges). This operation iteratively
947    /// removes edges that are part of such terminal paths until no more such branches exist.
948    ///
949    /// It first removes purely external edges from the `subgraph`'s internal part,
950    /// then iteratively prunes edges that form degree-1 connections within the subgraph's context.
951    /// Finally, it fixes the `hairs` of the `HedgeNode` to be consistent.
952    ///
953    /// # Parameters
954    /// - `subgraph`: A mutable reference to the `HedgeNode` to be pruned.
955    pub fn cut_branches(&self, subgraph: &mut HedgeNode) {
956        let nodes = AHashSet::<NodeIndex>::from_iter(
957            subgraph
958                .internal_graph
959                .included_iter()
960                .map(|i| self.node_id(i)),
961        );
962        self.remove_externals(subgraph);
963
964        let mut has_branch = true;
965        while has_branch {
966            has_branch = false;
967
968            for n in &nodes {
969                let int = self.iter_crown_in(subgraph, *n).collect::<Vec<_>>();
970                let first = int.first();
971                let next = int.get(1);
972
973                if let Some(first) = first {
974                    if next.is_none() {
975                        subgraph.internal_graph.filter.sub(*first);
976                        subgraph.internal_graph.filter.sub(self.inv(*first));
977                        has_branch = true;
978                    }
979                }
980            }
981        }
982
983        self.nesting_node_fix(subgraph);
984    }

2426                        let (mapped_node, parallel): (_, S::Base) = new_self

2433                                    mapped_node

2435                                    *a
2436                                }

2456            }
