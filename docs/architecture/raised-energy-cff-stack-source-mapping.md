## Ownership boundaries

- Commit 1 contains the symbolic, numeric and tensor prerequisites, including those required by Vakint. Its three compact-parser regressions use public execution results and an independent weighted Minkowski oracle. The powered-dot regression uses the whole-numerator FORM API available at this boundary; its explanatory comment stays with the required freshening implementation.
- Commit 2 owns shared rational coefficients, independent repeated occurrences, generation, caching and the shared contour convention. Commit 3 owns core consumers, source assignment, exact reconstruction and denominator-incidence handling. Its GL00 T0+T1 and GL04 T0+T1+T2 child certificates check complete signed numerators and separate denominator contracts; full-route numerical tests provide complementary coverage.
- Commit 4 owns command-driven evaluation, persistence and the scalar matrix. Its additional-weight Serde adapter encodes structured keys as pairs and retains the original generic deserialization bound. JSON/bincode round trips and physical inspection compare complete weights and numerical outputs. Archived numerical fixtures remain separate from the acceptance oracles.
- Commit 5 owns physical phases and model sewing. Its initial-state subtraction retains fixed-momentum bridge vertices unless an endpoint touches the initial cut; the helper signature and callers belong together.
- Commit 6 owns both Vakint input modes and the complete `tensor`/`tensor_index` API. It extends the powered-dot angular-average regression to both modes while retaining the same independent oracle. No temporary compatibility layer separates the migration from its callers.
- Commit 7 contains the integrated motivation audit, benchmark inventory and evidence, powered-dot investigation, current source mapping, per-commit review and validation documents. Benchmark source identities and measurements remain pinned; separate current dispositions record the completed JSON/parser changes without relabelling old results as fresh validation.
- Generated schemas accompany their defining implementation: foundational metadata in 1, core settings in 3, command workflows in 4, phase/model fields in 5 and dimensional settings in 6. Architecture documentation follows the same functional boundaries.

The three archived legacy CFF decimal fixtures have unverified derivations and remain outside the automatic suite. Their provenance is documented without claiming numerical acceptance coverage.
